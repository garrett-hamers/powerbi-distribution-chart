# Changelog

## Unreleased

- Align two TMDL details in the sample semantic model with the only sample configuration known to open in Power BI Desktop. The DAX expression under `source =` was indented three tabs where every sibling uses four, and TMDL takes the first expression line's indentation as the baseline for the whole block, so the depth changes how everything beneath it parses. Separately, three calculated-table columns declared an explicit `dataType`, which no sibling does: on a calculated table the column types come from the `DATATABLE` declaration in the partition, so restating them can only agree redundantly or disagree. Of six sibling visuals this project was the sole outlier on both counts, and it shares that divergence with the one whose sample demonstrably fails to open. Stated carefully: unlike the dangling reference below, neither of these can be shown to be causal without opening the sample in Desktop. They are departures from the configuration known to work, which is reason enough to align them and not reason enough to call them proven defects.
- Pin both TMDL details in `npm run audit:submission`, checked against the generator's output rather than left to the existing drift check. Drift compares the committed sample to whatever the generator currently emits, so editing the generator moves both sides together and drift stays silent — which is exactly how these two diverged unnoticed in the first place.
- Remove a dangling `SharedResources` resource package from the sample report. `report.json` declared that the `CY24SU10` base theme shipped as a file at `BaseThemes/CY24SU10.json`, and no such file was ever emitted. `CY24SU10` is one of the base themes built into Power BI Desktop: referencing it by name from `themeCollection.baseTheme` is correct and is retained, but a resource package asserts the item ships *inside the report*, so Desktop resolves the path, finds nothing, and fails to open the project. A sibling visual carrying the byte-identical declaration demonstrably fails to open in Desktop 2.150.2102.0, and the sibling whose sample opens correctly declares no `SharedResources` package at all. The defect is fixed in `scripts/build-sample-report.mjs`, which generates the sample, so it cannot come back on the next regeneration. Nobody has yet read the Desktop dialog body, so this is not proof that the dangling reference was the *only* thing wrong with the sample - it is a real defect, fixed, and the sample is not claimed to be confirmed working.
- Resolve every declared reference in the sample project against disk in `npm run audit:submission`, which already runs in CI. The check walks the `.pbip` artifact paths, the `.pbir` dataset reference, every resource package item, page and visual folder names, the embedded visual's own manifest resources, and the `ref table` entries in `model.tmdl` - 8 references in total - and fails when any of them resolves to nothing. Resource package paths are tried against every documented base directory for their package type and all of the attempted paths are printed on failure, so a miss cannot be dismissed as the audit guessing the wrong base. This deliberately is not schema validation: a JSON schema constrains shape, so a path to a file that does not exist is perfectly schema-valid, and a schema pass over a report Desktop refuses to open returns green.
- Assert the embedded copy of the visual under `CustomVisuals/` is byte-identical to the current `dist/` package rather than assuming it. A stale embedded copy ships a different visual than the one under test, and nothing else in the audit would notice.

- Stop the chart, its category labels and its status band from rendering outside the visual's own tile. A Power BI tile clips with `overflow: hidden`, so anything drawn past its edge is silently lost, and four separate constants in the layout were sized for a large tile and unable to shrink: a fixed 90px value gutter (reserving space for a value axis that is never drawn) plus a 24px edge margin exceeded an 80x80 tile outright and put the plot origin past the right edge; the 28px minimum box, 36px minimum hit target and 8px minimum marker radius could not shrink into a narrow category slot; SVG `<text>` neither wraps nor truncates, so a long category name or a full-sentence state message ran off both sides; and the ~100-character row-count sentence, free to wrap inside an absolutely positioned band, grew to 144px inside an 80px tile. Reserved bands now scale with the tile, every minimum glyph size is capped by the space actually available around its category, SVG text is measured against the real font and trimmed with an ellipsis, and the status band is bounded to a single line and dropped on tiles too small to carry it. Chrome degrades first: the box plots, the category labels and the accessible summary table survive at every size, and the diagnostics sentence stays in the root's accessible name, in every tooltip and beside the numbers in the summary table. Layout is unchanged on any tile large enough to afford the original values - the committed 1366x768 listing screenshots are byte-identical.
- Add `npm run layout-probe`: it renders the *packaged* `.pbiviz` bundle in real headless Chromium across 80 cases - five tile sizes down to 80x80, the formatting toggles in their default and non-default states, both writing directions, high contrast, and nine data scenarios - and measures every element's `getBoundingClientRect()` against the visual root's clipped box. This cannot be done in JSDOM: it has no layout engine, so every rectangle it reports is zero and a geometry assertion written against it can never fail. Elements inside a real scroll container, elements that are not painted, and elements clipped to zero area by `clip-path` are exempt; the exemptions are counted in the report, and the elements allowed to claim the `clip-path` one are pinned to the two screen-reader-only nodes so it cannot become a place where defects hide. The probe also rejects a `position: static` visual root holding absolutely positioned descendants, which would resolve against the initial containing block and escape the root entirely.
- Add `npm run prove-regressions`: each layout fix is reverted on its own, the visual is repackaged, and the probe is required to go red on the cases that fix governs. A fix that cannot be shown to fail without its patch is not proven, and the script fails if one stays green.
- Run CI on every push rather than only on `main`, and add the layout probe and the regression proofs to it, on Node 22 - the probe drives Chrome over the DevTools Protocol using the global `WebSocket`, which is only unflagged from Node 22. The packaged artifact is unaffected: a Node 20 runner and a local Node 24 build produced byte-identical `.pbiviz` files.
- Publish the built `.pbiviz` from CI as a downloadable `pbiviz-<commit-sha>` artifact, retained 90 days, and print its filename, byte count, and SHA-256 to the run log and run summary. The run that verified a commit is now the unambiguous source of the binary to submit, and the checksum is recoverable without downloading anything. `docs/partner-center-submission.md` records it as the canonical binary and notes that the SHA-256 is of the `.pbiviz` inside the ZIP GitHub wraps around downloaded artifacts.
- Make confirming the sample report renders **with data** an explicit step in the `.pbix` procedure, before **File > Save As**, with **Home > Refresh > Schema and data** as the fix if any table is empty or Desktop reports incomplete data. The committed project carries no cached model data, and saving while the tables are empty ships a `.pbix` with no data, which fails AppSource review. Documented in `docs/partner-center-submission.md` section 4.1, the generated `samples/README.md`, and the `npm run audit:submission` operator output, together with the check that a credential prompt at any point means something external has entered the semantic model. Whether Power BI Desktop evaluates this DAX calculated table on open is untested and is deliberately not asserted either way - the wording is correct whichever it does.
- Correct the claim that the calculated table has "nothing to refresh". It has no data source to authenticate against or connect to, but it still has to be evaluated before it holds rows.
- Fail the dependency audit on any advisory, not just high and critical. `npm run audit` and the CI step now run a plain `npm audit`, matching the other five visuals in the portfolio; `--audit-level=high` had been masking a moderate advisory the rest of the portfolio already fails on. `npm run audit:production` keeps `--omit=dev` but drops the same threshold, so it differs from `npm run audit` only in scope.
- Pin `hono` to `^4.12.34` through `overrides` to clear GHSA-8j4g-w8fx-2239, a ReDoS in hono's CORS middleware reached transitively through `powerbi-visuals-tools`.

## 1.0.1

Prepares the visual for its Microsoft AppSource / Partner Center submission.

- Ship the packaged visual icon as a real 20x20 PNG rendered from `assets/icon.svg`. Previously `assets.icon` pointed at an SVG, which `powerbi-visuals-tools` relabels as `assets/icon.png` in the packaged manifest while embedding an `image/svg+xml` payload, without validating the format or the dimensions. This version bump exists because that correction changes the packaged bytes, and the storefront distributes artifacts from version-keyed paths.
- Point the packaged support URL and author email at the published Atlyn support channels.
- Add three real 1366x768 AppSource listing screenshots captured from the packaged visual, plus the offline harness and deterministic sample dataset behind them.
- Add an AppSource EULA, a Partner Center submission dossier, and a deterministic `npm run audit:submission` gate wired into CI and the certification audit.
- Record the owner-confirmed free, non-transactable AppSource listing decision and its separation from the Atlyn Stripe subscription.
- Add a deterministic offline sample report project (PBIP + PBIR + TMDL) whose data is a DAX calculated table with no data source object, and with the built visual embedded for offline rendering.
- Pin the line endings of packaged text assets so the PBIVIZ is byte-identical across Windows and Linux, not just reproducible per operating system.
- Preserve Tukey outliers when a distribution has zero IQR.
- Keep category identities, locale-aware dates, and interaction permissions aligned with host data.
- Add direct Power BI security linting, certification-audit packaging, CI, and release metadata.
- Add a checked-in Partner Center-ready 300x300 PNG logo and deterministic release-metadata generation.

The visual GUID is unchanged, so v1.0.1.0 is the same product as v1.0.0.0 and existing reports keep working.
